Полуавтоматический верификатор компилятора

Доказывает, что шаги понижения MLIR от исходного кода до LLVM не превращают безопасный код в небезопасный. Под компилятором имеется в виду любой MLIR-компилятор.

Под безопасностью понимается функциональная эквивалентность, а также устойчивость к тайминг-атакам. Иные формы уязвимости — кэш, энергопотребление — здесь не рассматриваются.

В качестве основного метода выбран FCVD: он даёт трансляцию диалектов в SMT и гарантию безопасности через самокомпозицию SMT при наличии всех трансляций. Минус — для корректной работы необходимо, чтобы каждая операция MLIR из трансляции имела отображение в SMT.

Полуавтоматика достигается за счёт двух вещей:

  1. трансляции между уровнями пишутся только один раз — с течением времени все основные преобразования переиспользуются;
  2. если отображения в SMT нет, всегда можно реализовать макро-шаблоны — декларативные правила вида «цикл с границами [S, E, St] и телом F(x) эквивалентен скелету из четырёх блоков cf.br», доказываемые один раз и дальше применяемые без перепроверки.

То есть все доказательства формируются единообразно единым алгоритмом: при доказательстве безопасности нового компилятора алгоритм действий тривиален.

Диалекты и понижения между ними

Узел — диалект MLIR, ребро — шаг понижения из конвейера компилятора, взятый из его исходников. Чем жирнее рамка узла, тем больше компиляторов через него проходят, и рядом стоит «×N»: это и есть точки переиспользования, ради которых трансляция пишется один раз. Ребро в обратную сторону (справа налево) рисуется дугой снизу — такие шаги действительно есть.

  • ✓ шаг с доказанной спецификацией
  • ✕ шаг, доказанно ломающий constant-time (пунктир)
  • шаг не проверялся

Понижения по отдельности

Стоимость каждого шага

«Операции на входе» — это операции входных диалектов шага, встречающиеся в корпусе компилятора. Именно они определяют, можно ли прогнать через шаг реальную программу. Оценка времени считается из двух ручек ниже, а не из измерений: измерено только время солвера.

Измерено косвенно: 4 трансляции, написанные для этой работы, — от 80 до 253 строк Python. Человеко-время не инструментировалось. Считайте это порядком величины, а не замером.

Основной расход — прочитать паттерн в исходниках компилятора. Прогон солвера при этом занимает 0.13 с (медиана), то есть в счёт не идёт.

Сколько стоит компилятор целиком

Здесь всегда все шесть, по возрастанию, — фильтр компилятора действует только на таблицу выше.

Считается только то, что компилятор действительно использует: операции без перевода в тех диалектах, которые встречаются в его конвейере, по его собственному тестовому корпусу. Это оценка объёма, а не сложности — hw.module одна механическая трансляция, onnx.Conv тоже «одна».

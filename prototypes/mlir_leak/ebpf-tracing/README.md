# ctprobe — an eBPF PMU constant-time probe for MLIR-lowered kernels

`ctprobe` measures whether a compiled kernel's **microarchitectural behaviour
depends on a secret**. It attaches an eBPF uprobe/uretprobe to a victim
function, reads CPU performance counters (cycles, L1D-miss, dTLB-miss) across
each call, and runs a Welch *t*-test comparing a fixed-secret input class
against a random-secret class. `|t| > 4.5` on a counter means that counter's
behaviour depends on the secret — a leak on that channel.

It is the **real-silicon measurement layer** of a layered non-interference
stack: the static, all-inputs layer is a taint analysis (Staging_NI); the
deterministic, architectural layer is `mlir_leak` (Valgrind memcheck taint);
`ctprobe` corroborates their verdicts on real hardware and adds per-channel
magnitude and a detectability-threshold story the other layers cannot give.

## What it measures

| Counter    | Raw encoding (P-core)              | Channel it reveals                                   |
|------------|------------------------------------|------------------------------------------------------|
| `cycles`   | `0x3c` CPU_CLK_UNHALTED.THREAD     | timing / **control-flow** (secret-dependent branch)  |
| `l1dmiss`  | `0x08d1` MEM_LOAD_RETIRED.L1_MISS  | L1 data-cache **pressure** (secret-dependent access) |
| `dtlbmiss` | `0x0e12` DTLB_LOAD_MISSES.WALK_COMPLETED | page-granularity **pressure** (TLB / page walks) |

**Scope, stated honestly.** These counters measure event *magnitude* (how many
cycles, how many misses), not *identity* (which cache line, which page). A leak
where a secret selects *which* resident cache line is touched while every access
still hits produces no change in miss count — it is invisible here by
construction, and is Microwalk's job (deterministic address trace). `ctprobe`
owns the timing channel, the cache/TLB *pressure* channels, and the real-hardware
view. It is **dynamic**: a `<-- LEAK` verdict is a sound positive, but a clean
result means "no leak on the inputs tested," not a proof — which is why a sound
static analysis sits above it in the stack.

## How it works

1. A victim kernel is wrapped in `mw_run(unsigned long class, unsigned long iters)`.
2. eBPF uprobe on `mw_run` entry snapshots the counters; uretprobe on return
   reads them again. The **delta** is that call's cost.
3. A driver calls `mw_run` in an interleaved class-0 / class-1 loop, tens of
   thousands of times, half fixed-secret, half random-secret.
4. The BPF program accumulates, per class, running moments (count, sum,
   sum-of-squares) in a per-CPU map — enough to compute mean and variance.
5. Userspace reads the map at Ctrl-C and computes a Welch *t* per counter.

Everything is pinned to one isolated core so the counter delta is purely the
victim's cost. The counter is armed only on that core (auto-detected from the
`taskset` affinity), which is also what makes it work on hybrid CPUs.

## Files

| File               | Role                                                              |
|--------------------|-------------------------------------------------------------------|
| `ctprobe.bpf.c`    | eBPF program: uprobe/uretprobe on `mw_run`, reads PMU counters, accumulates per-class moments in maps |
| `ctprobe.c`        | userspace loader: opens counters, attaches probes, computes the Welch *t* report |
| `ctprobe.skel.h`   | auto-generated by `bpftool gen skeleton` — embeds the compiled BPF object; do not edit |
| `Makefile`         | builds the BPF object, generates the skeleton, links the loader   |
| `ctprobe_shim.c`   | defines `mw_run(class, iters)` — the victim; wraps an `mlir_leak` kernel |
| `ctprobe_driver.c` | calls `mw_run` in an interleaved class-0/class-1 loop so the probe fires |
| `run_ctprobe.sh`   | orchestrator: builds everything from the kernel objects and runs the full sequence |
| `measurement-rig.sh` | isolates a core (governor, turbo, C-states, IRQs, `perf_event_paranoid`) for low-noise measurement |

## Requirements

- Linux with a **BTF-enabled** kernel (`ls /sys/kernel/btf/vmlinux` must exist).
- `clang` **with the BPF backend** (`clang --print-targets | grep bpf`), plus
  `llvm`, `libbpf-dev`, `bpftool`, `linux-headers-$(uname -r)`,
  `linux-tools-$(uname -r)`. On Debian/Ubuntu:
  `sudo apt install clang llvm libbpf-dev bpftool linux-headers-$(uname -r) linux-tools-$(uname -r)`
- Root (for `perf_event_open`, uprobe attach, and the rig).
- `perf_event_paranoid <= 0` (the rig sets it to `-1`).
- The `mlir_leak` kernel objects (`*.P0_O0.o`) from `python3 run_mlir.py`,
  copied out of `build/` **before** the next run wipes it.

## Build

```sh
# vmlinux.h is required for struct pt_regs / bpf_perf_event_value:
bpftool btf dump file /sys/kernel/btf/vmlinux format c > vmlinux.h

# build with a clang that has the BPF backend (NOT a custom LLVM built for MLIR only):
make CLANG=clang
```

If the paste-prone `make clean` target misbehaves, clean explicitly so the BPF
object and skeleton regenerate:

```sh
rm -f ctprobe ctprobe.bpf.o ctprobe.skel.h
make CLANG=clang
```

Makefile recipe lines must begin with a **tab** (a paste that turns tabs into
spaces gives `*** missing separator`).

## Run

Everything must be pinned to **one core, and that core must be a P-core** on
hybrid CPUs (`ctprobe` opens the `cpu_core` PMU; opening it on an E-core fails
with `ENOENT`). Find the P-core list:

```sh
cat /sys/bus/event_source/devices/cpu_core/cpus   # pick a core from this list
```

### Manual (two terminals)

```sh
sudo ./measurement-rig.sh setup 1          # isolate a P-core (recommended)

# terminal 1 — attach the probe (auto-detects the pinned core from taskset):
sudo taskset -c 1 ./ctprobe ./ct/libmask.so mw_run

# terminal 2 — drive it: <lib> <rounds> <iters>, interleaved class 0/1:
taskset -c 1 ./ctprobe_driver ./ct/libmask.so 20000 1000

# back in terminal 1: Ctrl-C to print the report
sudo ./measurement-rig.sh restore
```

The driver **must** be pinned to the same core as the probe — the counter is
armed only there, and `mw_run` must execute there for the uprobe to read it.

### One-shot orchestrator

```sh
export CLANG=clang
export MLIR_LEAK=~/path/to/prototypes/mlir_leak
sudo -E ./run_ctprobe.sh <P-core>
```
